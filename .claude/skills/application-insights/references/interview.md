# Interview

Run this after gathering sources and drafting privately. The aim is to replace intent with what actually happened on site. Every correction the user had to make in the session this skill came from would have been caught by one of these questions.

## How to ask

- **Confirm-or-correct, not open questions.** "I have the robot as mounted by the customer on a pedestal next to the booth - correct?" is answered in seconds. "How was the robot mounted?" hands the work back.
- **Batch it.** Use the options tool for up to three quick choices and put the rest as a numbered list in the same message, so the user can answer everything in one pass.
- **Flag the source of each assumption** when it came from planning material ("the scope doc says the encoder sits in ATEX zone 2/22 - did that hold on site?"). Those are the ones most often wrong.
- **"Don't know" is fine.** Leave a visible `[...]` gap on the slide and say so in the summary rather than guessing.
- **Ask again later in the build** when new material (photos, videos, a second draft deck) raises new questions. One round is rarely enough.

## The sweep

### The case
1. What exactly does the robot do? (Whole part or touch-up, reachable from one side or all round, which parts, cycle and conveyor speed.)
2. What did the customer do before - manual process, which equipment, how many operators?
3. What was the goal and what did the customer care about most?

### Who did what
4. Who integrated what: robot mounting, booth/cell, paint or process equipment (e.g. a distributor), wiring, safety, CE/ATEX?
5. How was the cabling and wiring split agreed and done on site?
6. Was there an integrator/partner, or did the customer act as integrator?

### Setup as built
7. Robot placement and mounting (pedestal, slider, orientation) - confirm against photos.
8. Tool and joystick mounting, trigger signals: how were tool triggers and the manual gun trigger actually obtained?
9. Cameras / lighthouse placement, any coverage problems.
10. Robot program and workflow: physical buttons, part trigger, conveyor tracking, joint limits.
11. Software versions actually installed.

### What went wrong or differed from the plan
12. What broke, failed or behaved badly on site - and the root cause if known?
13. Which pre-project assumptions were wrong on site (zones, existing hardware, dimensions, speeds, customer resources)?
14. What was improvised on site, and is it a solution to reuse?
15. What is still open: replacement parts, final acceptance, follow-up visits?

### People and process
16. Which operators/painters taught the robot, and their background and tech familiarity? (Feeds the Operator slide; drop the slide if unknown.)
17. Process steps before and after the robot (hanging, pretreatment, oven, unloading)? (Feeds "Process today"; drop if unknown.)

### Wrap-up
18. Follow-up projects or upsell (check Pipedrive and Project Tracking first, then confirm).
19. Confidential? (Ticks the Confidential checkbox on the insights item.)
20. Which photo best shows X? Ask when the material does not clearly show something the user wants shown (e.g. all cameras in relation to the workspace).

## Turn answers into learnings

A good key learning is an instruction for the next project, backed by what happened here:

- Weak: "ATEX sensor checklist"
- Strong: "Ask for photos, videos or documents behind every site fact (ATEX zones, conveyor speed, wheel diameter, smallest part, existing hardware); the customer's answers alone proved wrong"
